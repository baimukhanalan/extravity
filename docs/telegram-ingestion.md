# Сбор возможностей из Telegram

Учебный модуль проекта: автоматический сбор объявлений о конкурсах, олимпиадах и
программах из Telegram-каналов, разбор свободного текста в структурированные
данные и передача их в очередь модерации каталога.

Реализованы два независимых пути:

| Путь | Технология | Что нужно | Где код |
|---|---|---|---|
| **A. Чтение публичных каналов** | MTProto (Telethon), Python | свой аккаунт Telegram, `api_id`/`api_hash` | `apps/parser/tgcollect/` |
| **B. Пересылка поста боту** | Bot API, webhook в Next.js | токен бота | `app/api/telegram/webhook/route.ts` |

Оба пути заканчиваются одним и тем же кодом — `lib/ingest.ts`. Это сделано
намеренно: дедупликация, trust score и правило «ничего не публикуется без
модератора» не должны расходиться между источниками.

---

## 1. Почему MTProto, а не Bot API

Bot API устроен так, что бот видит сообщения канала, **только если он добавлен
в этот канал администратором**. Для своего канала это идеальный вариант — посты
приходят мгновенно, без опроса. Но для учебной задачи «собрать объявления из
десятка чужих тематических каналов» это неприменимо: прав администратора там нет
и не будет.

MTProto — это протокол, на котором работают обычные клиенты Telegram. Библиотека
[Telethon](https://docs.telethon.dev/) реализует его на Python. Авторизовавшись
своим аккаунтом, программа видит ровно то же, что видит человек в приложении:
публичные каналы, на которые можно зайти по ссылке. `api_id` и `api_hash`
Telegram выдаёт сам на [my.telegram.org](https://my.telegram.org) именно для
разработки таких клиентов.

**Границы, заложенные в код:**

- только **публичные** каналы; приватный отдаёт `ChannelPrivateError`, канал
  пропускается с понятной ошибкой (`client.py`);
- сохраняются только текст поста и его постоянная ссылка — ни списков
  подписчиков, ни авторов, ни личных сообщений;
- `FloodWaitError` (сигнал Telegram «слишком часто») **обрабатывается ожиданием**
  на указанное сервером время, а не обходится сменой аккаунта или прокси;
- между каналами пауза, на канал — лимит постов за прогон, глубина ограничена
  30 днями;
- файл сессии Telethon — это фактически ключ от аккаунта, поэтому он в
  `.gitignore` и никогда не попадает в репозиторий.

Для боевого продукта правильнее договориться с владельцами каналов и добавить
бота администратором (путь B). Для учебной работы путь A показателен: он
демонстрирует работу с бинарным протоколом, авторизацию, состояние и обработку
серверных лимитов.

## 2. Архитектура конвейера

```
Telegram (публичные каналы)
        │  MTProto, Telethon
        ▼
  fetch_posts()            client.py   — новые посты с id > offset, FloodWait, ссылки из entities
        │
        ▼
  baseline()               extract.py  — детерминированный локальный разбор
        │
        ▼
  POST /api/parser/ingest  ingest.py   — тот же контракт, что у HTML/RSS-парсера
        │
        ▼
  ingestCandidates()       lib/ingest.ts — валидация, дедуп, trust score
        │
        ▼
  Opportunity: PENDING_REVIEW  →  /admin/moderation  →  каталог
```

Ключевое свойство: **из канала в каталог нет прямого пути**. Любой кандидат
получает статус `PENDING_REVIEW` (или `SUSPICIOUS`, если trust score ниже порога)
и ждёт модератора.

### Состояние между запусками

`tgcollect/state.py` хранит отдельно id последнего обработанного нового поста и
курсор догрузки более старых сообщений. Сборщик сначала берёт свежие сообщения,
а затем листает историю в пределах настроенного возраста постов. Оба курсора
двигаются **после** успешной отправки: сбой повторяет пачку, а не пропускает
пост; дубликаты отсекаются при приёме.

## 3. Разбор свободного текста

Пост в Telegram — не структура, а текст с эмодзи, переносами и разговорными
формулировками. Разбор выполняется локальными детерминированными правилами.

### Детерминированный разбор (`baseline`)

Работает всегда, без сети и без API-ключа. Отвечает за то, что можно прочитать
буквально:

| Поле | Как определяется |
|---|---|
| дедлайн | дата рядом со словом-маркером («дедлайн», «срок подачи», «заявки до») |
| ссылка на подачу | из всех URL выбирается похожая на форму (`forms.gle`, `/apply`, `tally.so`) |
| цена | «бесплатно» → 0; иначе число рядом с ₸/тг/тенге |
| класс, возраст | диапазоны «8–11 класс», «14-18 лет» |
| город | по основе слова, чтобы ловить падежи: «в Астане» → Астана |
| формат | онлайн + город → HYBRID; только онлайн → ONLINE; иначе OFFLINE |
| категория | ключевые слова, 20 категорий каталога |

Две детали, которые пришлось продумать отдельно:

**Год у даты без года.** Пост «дедлайн 20 марта» опубликован в феврале — значит,
март того же года. Если считать год от даты *запуска* парсера, все архивные посты
уезжают на год вперёд. Поэтому точкой отсчёта служит **дата публикации поста**
(`reference_date`), а дата запуска — только запасной вариант.

**Что вообще считать объявлением.** Каналы публикуют много постороннего. Фильтр
`looks_like_opportunity` пропускает текст, если в нём либо несколько слов из
«лексики объявлений», либо одно такое слово плюс структура объявления —
формулировка дедлайна и ссылка. Второе правило добавлено после того, как первая
версия отбросила реальный пост про летнюю школу, где нужное слово встречалось
один раз.

### Telegram-контент не передаётся языковой модели

Для Telegram-сборщика разрешён только локальный разбор. Содержимое каналов не
отправляется в Claude или другую AI/ML-систему — это ограничение условий
Telegram API. Необязательный LLM-слой других источников к Telegram-пайплайну
не подключён.

## 4. Дедупликация и доверие

Один и тот же конкурс приходит из нескольких каналов и с сайта организатора.
Совпадение ищется по трём признакам (`lib/ingest.ts`): та же ссылка-источник, та
же ссылка на подачу, либо совпадение названия и организатора. Дубликат не
создаёт новую запись — он обновляет `lastCheckedAt` и, если появился, дедлайн.
Так повторный обход работает как ревалидация.

`trustScore` считается по сигналам источника. Telegram получает **штраф**: пост в
канале — это наводка, а не первоисточник, его ещё нужно сверить с сайтом
организатора. Ниже порога запись помечается `SUSPICIOUS` и показывается
модератору отдельно.

## 5. Как запустить

### Без ключей и без Telegram — демонстрация разбора

```bash
cd apps/parser
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python run_telegram.py --demo
```

Прогоняет шесть встроенных примеров постов (`tgcollect/demo.py`): четыре должны
превратиться в кандидатов, два — быть отброшены. Годится для показа на защите:
не зависит ни от сети, ни от того, что сегодня опубликовали в каналах.

### С реальными каналами

```bash
# 1. Ключи приложения с my.telegram.org → apps/parser/.env
#    TG_API_ID=... TG_API_HASH=...

# 2. Разовая авторизация аккаунта. Код придёт в Telegram —
#    эту команду запускаете вы сами, в своём терминале.
python run_telegram.py --login

# Если код не приходит: новая сессия по QR в интерактивном терминале сервера
python run_telegram.py --login-qr

# 3. Для разового ручного прогона укажите каналы в channels.yaml (username без @).
#    Непрерывный сборщик сам обнаруживает публичные и закрытые каналы из подписок аккаунта;
#    channels.yaml задаёт для них категорию, лимит и явное отключение.

# 4. Пробный прогон: разбирает и печатает, никуда не отправляет
python run_telegram.py --dry-run --channel имя_канала

# 5. Боевой прогон: кандидаты уходят в очередь модерации
python run_telegram.py
```

Непрерывный сборщик обновляет набор подписанных каналов примерно каждые 10 минут
без отдельного scheduled task. Он игнорирует личные чаты и группы. Закрытые каналы
учитываются только пока аккаунт остаётся их участником. Новые каналы получают лимит 20 последних постов для первого
прохода и статус `trusted: false`; подходящие объявления всё равно попадают только
в очередь модерации, а не сразу в каталог. Явный `enabled: false` в
`channels.yaml` исключает канал, даже если аккаунт на него подписан.
Медиа из закрытых каналов не копируются в публичное хранилище: такой пост
остаётся кандидатом до проверки источника и добавления медиа с подтверждёнными
правами использования.

## 6. Роль ИИ в проекте

Стоит разделить два разных применения — на защите об этом почти всегда спрашивают.

**ИИ внутри продукта (runtime).** Для данных из Telegram языковая модель не
используется. Посты обрабатываются локальными правилами, а решение о публикации
всё равно принимает модератор. LLM может применяться в других продуктовых
функциях только к данным, для которых это разрешено источником и пользователем.

**ИИ при разработке.** Код писался в паре с Claude (Claude Code): постановка
задачи, генерация модулей, разбор ошибок. Что это дало и чего не отменило:

- быстро закрылась рутина — схемы, регулярные выражения, обвязка CLI, тесты;
- ошибки всё равно находились прогоном, а не чтением: первая версия фильтра
  отбрасывала корректный пост про летнюю школу, а сборка ISO-строки дедлайна
  сдвигала время на пять часов — оба дефекта видны только по факту запуска;
- поэтому основная работа сместилась с набора текста на **проверку**: офлайн-
  фикстура из шести постов и 196 тестов существуют именно как способ не верить
  сгенерированному коду на слово.

Вывод, который честно защищать: ИИ ускоряет написание кода, но не снимает
ответственность за его корректность — и требует построить проверку раньше, чем
обычно.

## 7. Ограничения и что можно улучшить

Известные ограничения текущей версии:

- **Альбомы.** Пост, разбитый на несколько сообщений с медиа, обрабатывается по
  одному сообщению; текст описания может оказаться в другом сообщении группы.
- **Формат по умолчанию.** Если в тексте нет ни «онлайн», ни города, ставится
  `ONLINE`; модератор должен проверить это поле перед публикацией.
- **Только русский.** Казахоязычные посты разбираются частично (несколько
  маркеров есть), английские — нет.
- **Нет обратной связи от модератора.** Правки модератора не возвращаются в
  экстрактор, хотя это самый очевидный источник данных для его улучшения.

Про Instagram и про то, где вообще проходит граница допустимого сбора —
[instagram-and-scraping.md](instagram-and-scraping.md).

Направления развития: разбор альбомов как одного поста, обучение правил на
исправлениях модератора, расширение на казахский, и приоритезация каналов по
доле кандидатов, доживших до публикации.
