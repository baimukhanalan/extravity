# Внешний парсер Extravity: как он работает и как довести до автоматизации

> Актуально на 15 сентября 2026 года. Описывает текущий локальный код. Изменения
> этого дня ещё не развёрнуты на отдельном parser hosting и не авторизованы живыми
> Telegram/Meta credentials.

## Короткий ответ

Сейчас внешний parser — это три независимых входа:

```text
Официальные сайты / RSS ─┐
Telegram allowlist ──────┼→ извлечение фактов → нормализация → дедупликация
Instagram hashtags ─────┘                    ↓
                                  очередь модерации Extravity
                                             ↓
                                    публикация человеком
```

Он **не читает все Telegram-каналы и весь Instagram**. В текущей конфигурации:

- включён только локальный демонстрационный веб-источник;
- список Telegram-каналов пуст;
- список Instagram-хештегов пуст;
- Telegram/Instagram schedules выключены;
- живых `TG_API_ID/HASH`, Telethon session, Meta token и persistent hosting пока нет.

То есть код готов к controlled pilot, но реального внешнего массового сбора сейчас
не происходит.

## 1. Сайты и RSS

### Что делает машина

1. Берёт только включённые записи из `sources.yaml`.
2. Проверяет robots.txt и выдерживает паузу.
3. Ищет schema.org Event/JSON-LD, RSS, текст страницы и OpenGraph.
4. Извлекает название, организатора, сроки, возраст/класс, цену, формат и ссылку.
5. Нормализует поля и отправляет batch в `/api/parser/ingest`.
6. Приложение валидирует, ищет дубликаты, считает trust score и создаёт запись.

### Где нужен человек

- один раз разрешить и настроить источник;
- проверить качество dry-run;
- модерировать недостаточно надёжные карточки;
- реагировать на изменение верстки, robots.txt и жалобы.

### Что можно автоматизировать полностью

Официальные RSS/API/структурированные страницы — лучший кандидат. Для заранее
проверенного источника карточка может публиковаться автоматически только когда есть
application URL, дедлайн, высокая confidence и включён отдельный feature flag.

## 2. Telegram через отдельный пользовательский аккаунт

### Что делает машина

1. Telethon открывает session отдельного аккаунта.
2. Читает только `enabled`-каналы из `channels.yaml`.
3. Первый запуск берёт последние N постов; следующие — только ID выше offset.
4. Склеивает Telegram-альбомы, сохраняет текст, скрытые ссылки и permalink.
5. Локальными правилами определяет, похож ли пост на возможность.
6. Извлекает факты и отправляет кандидатов в общую очередь модерации.
7. После подтверждённого ingest сохраняет offset.

Telegram-контент не идёт в LLM. Длинный FloodWait не блокирует worker: job возвращает
`next_retry_at`. При частичном сбое offset не двигается, поэтому кандидат не теряется.
Одна session защищена межпроцессным lock.

### Где нужен человек

- получить `api_id/api_hash` и один раз завершить вход с двухфакторной защитой;
- юридически/операционно утвердить каждый источник;
- проверить 20–50 постов первого dry-run;
- сверить Telegram-наводку с официальным сайтом;
- решить, публиковать или отклонить карточку;
- обрабатывать жалобы и отзыв разрешения.

### Почему не «все публичные каналы»

Техническая видимость не даёт права на массовое повторное использование. Telegram
ограничивает доступ к user-generated content обычным предназначенным использованием
и прямо запрещает scraping/indexing/aggregation для AI/ML-разработки:

- [Content Licensing Terms](https://telegram.org/tos/content-licensing)
- [Telegram API Terms](https://core.telegram.org/api/terms)

Практический безопасный режим — официальный/партнёрский allowlist, минимум хранимого
контента, permalink, обязательная проверка источника и юридическое подтверждение модели.

## 3. Telegram-бот

Это не parser-account. Бот — отдельный объект Bot API.

Текущий бот умеет:

- привязать Telegram к аккаунту Extravity одноразовой 15-минутной ссылкой;
- отправлять уведомления;
- принять вручную пересланный пост;
- для ученика создать user submission;
- для сотрудника отправить извлечённого кандидата в модерацию;
- отключить связь через `/stop`.

Человек нужен только для осознанной пересылки. Это самый безопасный Telegram-путь
для ранней beta: ничего не читается фоном, пользователь сам выбирает конкретный пост.

## 4. Instagram

### Что делает машина

1. Работает через официальный Instagram Graph API, не через HTML scraping.
2. Использует Business/Creator account и reviewed Meta app.
3. Берёт только настроенные `enabled`-хештеги.
4. Получает недавние публичные media fields: caption, permalink, timestamp и тип.
5. Отбрасывает записи без caption/permalink.
6. Применяет тот же extractor и отправляет кандидатов в модерацию.
7. Перед scheduler делает официальный token/account/source preflight, показывает
   оставшийся срок token/data access и не запускается при недостающих scopes.
8. Архивирует карусели и Reel/video (или доступный официальный thumbnail), а при
   частичной ошибке media/ingest сохраняет cursor для безопасного повтора.

### Где нужен человек

- создать Business/Creator account, Meta app и пройти review;
- выбрать короткий список релевантных хештегов;
- подтвердить допустимое использование данных;
- проверить результаты и официальный источник возможности.

### Ограничения

- это не доступ ко всему Instagram;
- поиск идёт только по выбранным хештегам и доступным Graph API данным;
- организаторы часто размещают ключевые условия только на афише или в Stories;
- OCR афиш сейчас не реализован;
- Meta меняет версии, permissions и лимиты, поэтому интеграцию нужно регулярно
  перепроверять по официальной документации.
- долгоживущий токен всё равно должен перевыпускаться владельцем через Meta;
  сервис диагностирует срок, но не имитирует refresh через неофициальный flow.

## 5. Что изменено для автоматического режима

- веб, Telegram и Instagram получили отдельные интервалы;
- Telegram/Instagram выключены по умолчанию;
- scheduler не запускает два одинаковых job одновременно;
- Telegram требует явные абсолютные пути session/state на persistent volume;
- добавлены ручные admin endpoints `/run/telegram` и `/run/instagram`, оба по умолчанию
  работают как dry-run;
- если `PARSER_ADMIN_TOKEN` отсутствует, POST endpoints закрыты;
- Telethon обновлён до 1.45.0;
- добавлены transport/state regression tests; parser suite — 66/66.

## 6. Реальные уровни автоматизации

### Уровень A — human-in-the-loop beta, рекомендован сейчас

```text
машина находит → машина структурирует → человек проверяет → человек публикует
```

Подходит для Telegram, Instagram и новых сайтов. Даёт максимальный контроль качества
и позволяет измерить, какие источники действительно полезны.

### Уровень B — доверенные источники

```text
официальный RSS/API → автоматические проверки → автопубликация → периодический аудит
```

Разрешать только источникам организатора/государства/университета с устойчивой
структурой. Telegram и Instagram должны оставаться в модерации.

### Уровень C — партнёрская сеть, лучший конечный вариант

```text
организатор создаёт/обновляет запись → Extravity валидирует → публикация
                              ↘ webhook об изменении/отмене
```

Это надёжнее scraping: организатор отвечает за данные, дедлайны обновляются напрямую,
а Extravity хранит историю, trust и результаты.

## 7. Что ещё нужно для почти полной автоматизации

1. Выбрать parser hosting с одним worker и зашифрованным persistent volume.
2. Добавить БД-очередь с retries/dead-letter вместо одного синхронного batch.
3. Хранить source permissions, review date, owner contact и takedown status.
4. Автоматически открывать официальный application URL и сверять доступность/дедлайн.
5. Добавить version history и автоматическое снятие отменённых/просроченных карточек.
6. Подтверждать дубликаты по content hash и сходству полей.
7. Собирать moderator corrections и улучшать **детерминированные** Telegram-правила.
8. Добавить OCR только для источников, где это разрешено; Telegram-материалы не
   использовать для AI/ML.
9. Отслеживать source KPIs: publish rate, correction rate, duplicate rate,
   broken links, complaints и time-to-review.
10. Добавить партнерский organizer API/webhook и сделать его основным supply-каналом.

## 8. Рекомендуемое распределение источников

- 50–60%: официальные сайты, RSS, государственные и университетские страницы;
- 20–30%: organizer portal, партнёрский API и прямые submissions;
- 10–20%: Telegram/Instagram как discovery-сигнал;
- 0%: серый массовый scraping, private channels и неразрешённый доступ.

Полная автоматизация разумна для доставки и обработки, но не для решений о правах,
данных несовершеннолетних и высокорисковых платных возможностях. Эти контрольные
точки должны остаться у человека.
